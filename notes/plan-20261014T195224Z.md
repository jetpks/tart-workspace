ENTRY A (first — the outage)

ITERATION: zai-max-tokens

The port drops the models.json `maxTokens` fact on the floor and asks for a
995K-token completion cap, which z.ai rejects — every live turn dies with
`error: 400: The max_tokens parameter is illegal.：限制数值范围[1,131072]`.

Owner finding (live 2026-10-14T19:39Z, tart from repos/tart, default
zai/glm-5.3, ~/.tart/models.json declares contextWindow 1000000 and
maxTokens 131072):

1. Root cause chain — every link verified this session:
   - models.rb build_model (repos/tart/lib/tart/models.rb:228-238) stores
     `maxTokens` on Shapes::Model — and NOTHING reads it. The only `.max_tokens`
     consumers in tart read the GEM wire model (agent/chat.rb:178 facts
     readback; agent/loop.rb:645 summarization cap), never the catalog.
   - Agent::Loop#initialize (agent/loop.rb:158-161) and #switch_model
     (:315-323) call Chat#apply_facts WITHOUT `max_tokens:`.
   - Chat#apply_facts → Models.wire_model (models.rb:125-137):
     `max_tokens: max_tokens || context_window` → 1_000_000.
   - Gem clamp (fast-llm gems/completions/lib/fast/completions/protocol.rb
     :59-67): min(requested, window − estimate − 4096) → 995_895 for the
     failing session's shape (deterministic repro:
     tmp/repro_max_tokens_20261014.rb — prints 995895 today, 131072 with the
     catalog value threaded).
   - z.ai caps max_tokens at 131072 → 400 on every request.
2. pi parity (what pi sends for THIS models.json): 131072.
   - provider-composer.ts:198 `maxTokens: override.maxTokens ?? model.maxTokens`
     (:243 defaults 16384 when a definition declares none);
   - model-runtime.ts:727-734 `min(options.maxTokens, model.maxTokens)` into
     streamSimple;
   - openai-completions.ts:842-847 sends the key iff truthy (else omits),
     simple-options.ts:19-23 clamps to context.
3. Shape (spec owns detail): thread the catalog maxTokens through
   Agent::Loop (constructor + switch_model) → Chat#apply_facts →
   Models.wire_model, so the wire model carries the declared cap; the gem is
   NOT touched. Chat#summary_chat (agent/chat.rb:188-193) rides the same
   threading, and summarization_max_tokens (agent/loop.rb:643-646) then caps
   at the real value naturally. The spec session must also rule the
   undeclared-maxTokens fallback (models.json entry with no `maxTokens`):
   pi's shape is the 16384 default (provider-composer.ts:243), NOT the
   context-window fallback that 400s today — itemize the options and pick.
4. Verification beyond the battery: a unit pin that the built wire model for
   a zai catalog entry with maxTokens 131072 < contextWindow 1_000_000 sends
   max_tokens 131072 (build the request params through the gem's Protocol and
   assert the key); a second pin for the undeclared fallback shape the spec
   rules. A live rig/live-API check is NOT required (the repro is
   deterministic; the owner has burned the credits already).
