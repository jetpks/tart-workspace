## Ranked top-3 ports

1. **Mid-stream failure salvage (row 16).** Observed pi fix: the single catch-all in `stream()` (openai-completions.ts:707-728) converts ANY mid-stream throw into an `:error` event whose `error: output` still carries every streamed block, applied reasoning signatures, and usage — partial work is never silently discarded. Gem today: a socket reset or non-2xx mid-body unwinds through client.rb:96-99/:164-166 with the accumulator dropped. Port iteration: wrap `feed_stream`/POST failures in client.rb to run `deliver_terminal`'s error arm (emit `:error` with `accumulator.partial`) before raising; +client_spec and stream_cancel_spec cases. Highest daily-driver value — it is the same resilience class I61 exists for.

2. **Retry trigger classes (row 15).** Observed pi fix: `retryProviderRequest` (provider-retry.ts:25-38, 120-121) retries request creation exactly when `x-should-retry: true`, status missing, or status ∈ {408, 409, 429, 5xx}, honoring `x-should-retry: false` and `noRetryStatuses`; SDK runs with `maxRetries: 0` (openai-completions.ts:373). Gem: every failure raises once. Port iteration: a single-shot (or options-capped) retry around the POST in client.rb before first body byte, reusing the gem's error classes as triggers; +client_spec. Backoff policy explicitly out of scope.

3. **Encode scrub on outgoing strings (row 17).** Observed pi fix: `sanitizeSurrogates` applied at all five wire emission points so provider-adjacent junk (tool output, session text) can never break request serialization. Gem: live-verified `JSON::GeneratorError: source sequence is illegal/malformed utf-8` from `JSON.generate` on a lone surrogate — an exception class outside errors.rb's taxonomy that bypasses the terminal discipline. Port iteration: scrub in `Codec.to_wire_messages` (user text, tool-result text, assistant text); ~10 lines + codec_spec.

Runners-up (PORT, lower): row 14 index-map backfill (3 lines, correctness), row 18 id normalization, row 19 stop_reason on Message.
