The real parity gap: **pi's constrained-sampling (strict tools) wire layer is unimplemented in tart/fast-llm**. pi tags bash `constrainedSampling {type:"json_schema", strict:"prefer"}`; zai glm-5.3 compat `supportsStrictMode:true` → `makeStrictJsonSchema` (pi packages/ai/src/api/constrained-sampling.ts:90-124) rewrites the schema so EVERY property is required (optionals become `anyOf:[prop,{type:"null"}]`), `additionalProperties:false`, and `strict:true` rides the tool — glm is forced to emit `timeout` on every bash call. Evidence: same model+command via `pi -p` emitted `timeout:60`, died at 60s, model recovered with bounded re-runs, 140s total; my live tart session (2026-10-15T22-13-25) omitted `timeout` on 8/8 bash calls. fast-llm protocol.rb:79 sends parameters VERBATIM (no strict flag, no rewrite — by design, "the consumer's schema is the bytes"), tart's registry carries `supportsStrictMode` (schemas/models.rb:108) but nothing consumes it, and the fast-llm Tool DSL has no constrained-sampling seam. Blast radius: every optional param of every tool on strict-capable providers (read offset/limit, etc.), not just bash timeout — forced emission vs omission-at-will. Fix shape: port constrained-sampling into fast-llm (strict rewrite + per-provider compat resolution + `strict` wire flag) and consume it from tart's registry; gates: fast-llm wire_parity_spec + live A/B.
